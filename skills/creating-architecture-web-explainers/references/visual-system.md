## 2. 四套视觉风格预设 (Visual Presets)

1. **Cyber / HCH (赛博科技 - 默认)**：
   - 特征：深色海军蓝背景、克制辉光（Glow）、细描边网格（Grid Overlay）、0.6 默认透明度交互控制器；
   - 适用：Agent 运行机制、前沿系统架构、交互式产品解说。
2. **Signal Flow (信号流 / 管道)**：
   - 特征：强对比粒子流动、管道连线、动效强调数据流转方向；
   - 适用：微服务调用链、数据工程数仓入湖、ETL 处理流水线。
3. **Blueprint (工程蓝图)**：
   - 特征：网格坐标底纹、等宽字体打标、工程框线与端口标记；
   - 适用：网络拓扑、多区域物理基础设施、硬件/存储架构。
4. **Classic (经典出版 / 极简)**：
   - 特征：黑白高对比、低饱和度点缀、紧凑排版；
   - 适用：正式技术评审、PDF 导出与打印报告。

## 3. 标准 1200×630 分享卡片规范 (Share Cards)

为了方便在 GitHub README、技术博客、社交媒体和方案评审中分享，系统支持生成标准的 **1200×630 px** 尺寸卡片：
- **Canonical Share Card (全景分享卡)**：呈现系统完整架构概览与核心指标；
- **Route Share Card (路径分享卡)**：高亮某条特定调用链（如 `Browser -> API -> MySQL`），同时以半透明保留周围拓扑作为上下文；
- **Reach Share Card (可达范围分享卡)**：以某一节点为核心，展示其上游依赖与下游影响范围。

## 4. 排版与组件边界

- **正文基准**：桌面端不低于 16px、移动端不低于 16px；正文行高建议 1.5–1.7，严禁用过小字号或极低对比度伪造科技感；
- **Hero**：说明核心问题、范围和读者收益，不承载完整架构细节；
- **对比卡 (Comparison Card)**：用于并列方案与清晰取舍，不代替完整流程；
- **Stage**：用于纵向可连续阅读的单一语义阶段；
- **Slide**：用于四个及以上独立流程阶段；每屏一个阶段并保留操作上下文；
- **总结区 (Takeaways)**：回收核心设计结论与行动项。

导航栏默认 `opacity: .6`，`hover` 和 `focus-visible` 变为 1；键盘焦点必须具备清晰的高亮轮廓线。

---

## 5. 跨终端验收与无障碍 (A11y)

- **桌面端**：检查视觉层次、悬停反馈与键盘导航（Tab 键、左右方向键）；
- **移动端**：检查单列可读性、避免横向溢出，确保触控目标尺寸 $\ge 44 \times 44\text{px}$；
- **无障碍**：`prefers-reduced-motion: reduce` 必须关闭或显著降低动画时长至 0.01ms，确保辅助设备顺畅阅读。
