Agent Skills · Lifecycle Protocol

一个 Skill，如何被 Agent唤醒

Skill 是把专家经验封装成 Agent 能发现、能遵循、能验证的可复用工作方法。它不替代模型与工具，而是让它们在正确场景下按正确步骤协同工作。

// SKILL 是什么
触发条件+专业流程+按需资源

一份面向 Agent 的操作说明书：告诉它什么时候介入、接下来怎么做，以及用到哪些脚本、参考资料和模板。

// POSITIONING

Skill 不替代工具，它组织工具

Prompt、Skill、Tool 与 Agent Loop 在一次 Agent 运行中的不同职责。Skill 位于“能力编排层”：把判断、步骤、资源与验收标准组合成一套可重复调用的方法。

01

Prompt

表达意图

告诉模型这一次要做什么，灵活但通常是临时的，复杂任务容易遗漏步骤。

一次任务的输入
02

Skill

组织专业流程

把触发条件、步骤、约束和资源沉淀成可复用说明，让 Agent 稳定采用同一工作方法。

连接意图与执行
03

Tool / MCP

提供执行能力

负责读写文件、调用 API 或连接外部系统；它回答“能做什么”，但不规定完整业务流程。

被 Skill 按步骤调用
04

Agent Loop

驱动运行闭环

围绕任务反复进行判断、调用、观察、再判断，负责决定何时继续与何时停止。

承载 Prompt、Skill 与 Tool 的协作

适合 Skill 的理由

  • 流程可复用一次沉淀，多次调用
  • 上下文节省信息按需要逐层加载
  • 能力可组合可以串联多个工具
  • 经验可维护规则与模板集中更新

Skill 的边界

  • 不是确定性程序仍依赖模型正确理解
  • 不能替代工具没有权限就无法执行
  • 需要持续维护工具变化后说明要同步
  • 不承载应用运行不能替代框架与服务

01 · Skill

Skill 是 Agent 可复用的行动协议

Skill 不会自己运行。它把何时使用、怎样操作、调用什么资源、如何验收封装成 Agent 能遵循的说明，让一次成功方法可以被稳定复用。

02 · Skill

触发条件、操作步骤与按需资源组成 Skill

description 描述适用场景，正文规定操作与质量门槛，scripts、references 和 assets 提供执行所需的确定性能力与深度资料。

03 · Trigger

任务触发 Agent，能力目录已经在场

用户任务或更高优先级指令先进入 Agent；宿主同时提供已安装 Skill 的 name + description + path 轻量目录。不是 Skill 自己持续扫描，Agent 会在下一步依据目录做选择。

04 · Select

Agent 先查看轻量能力目录

能力目录像一份菜单：无需提前加载每份长说明，Agent 就能知道当前有哪些专业流程可用，并把任务与候选 Skill 放在一起判断。

05 · Select

description 是选择 Skill 的主要依据

它应明确使用场景、能力边界与必要限制。Agent 比较的是任务意图与这份使用契约，而不只是寻找几个相同关键词。SELECTION CONTRACT · 场景 + 能力 + 边界

06 · Select

显式点名或语义命中，完成选择

用户可以通过 @/$ 指定某个 Skill，也可以由 Agent 根据任务语义隐式匹配。示例任务同时要求 PDF、填写与校验，因此选择 pdf-fill。

07 · Load

选中后，完整加载主说明

只有确定使用时，Agent 才读取完整 SKILL.md。操作顺序、约束、工具选择和质量门槛此刻进入工作上下文。

08 · Load

资源沿执行路径按需展开

fill.py、fields.md 等资源无需一次性全部加载；Agent 执行到相关步骤并确认需要后，再读取或运行。

09 · Execute

Agent 按说明调用工具执行

Agent 读取字段规则、映射数据并运行脚本。Skill 负责组织行动，Tool / MCP 提供真实能力，两者在 Agent Loop 中协同完成任务。

10 · Observe

执行结果回到 Agent Loop 继续判断

工具输出会成为新的观察：字段是否完整、脚本是否报错、结果能否打开。若目标尚未满足，Agent 会据此决定下一次行动。

11 · Verify

验证通过才交付，失败则回到循环

Agent 对照 Skill 的质量门槛检查结果。未通过就回到加载或执行阶段继续处理；全部通过后，才把最终文件交付给用户。

12 · Recap

完整闭环：发现、选择、加载、执行、观察、验证

Skill 提供可复用方法，Agent Loop 负责判断与推进，Tool / MCP 完成真实操作；信息按需进入上下文，结果经过验证后才结束。

Why it scales

不是记住一切，而是知道何时加载什么

如果每个 Skill 的完整知识都永久常驻，上下文很快会被挤满。渐进式披露让 Agent 可以拥有庞大的能力目录，同时只为当前任务支付必要成本：轻量发现，精准加载，按需执行。

Design takeaway

  1. 把触发描述写成清晰的使用契约
  2. 让 SKILL.md 聚焦行动顺序与质量门槛
  3. 把长知识、脚本和模板拆成按需资源
  4. 用验证步骤定义真正的“完成”
