# Task 2 基线审查

| 审查项 | 评分 | 基线原话与判断 |
| --- | --- | --- |
| 1. 先建立“概念、关系、流程、权衡、结论”内容模型 | PARTIAL | 基线包含多个模型要素：`“用简洁卡片解释网关、消息队列、幂等、重试、熔断、可观测性等概念”`、`“以横向分层关系展示入口层、API 网关、三个业务服务、消息队列、数据层”`，以及 `“按步骤解释‘用户请求 → 入口层 → API 网关 → 对应业务服务 → 数据层 → 响应返回’”`。但方案先以 `“页面分为五个区域”` 组织，未先明确提出这五类内容模型；权衡仅有 `“适用场景和注意点”`，也没有明确结论层。 |
| 2. 按可独立理解的节点数明确选择纵向滚动或横向 Slide | MISS | 基线只规定架构图 `“以横向分层关系展示”`，并说 `“在窄屏下转为纵向堆叠”`；没有依据可独立理解的节点数选择整页纵向滚动或横向 Slide 的规则。 |
| 3. 横向模式定义按钮、页码、键盘、触控与首尾禁用状态 | MISS | 基线仅提出 `“提供‘主流程 / 异步事件 / 故障回路’流程切换”` 和 `“提供‘逐步播放’控制”`。未定义横向 Slide 的导航按钮、页码、键盘、触控操作或首尾禁用状态。 |
| 4. 将 HCH.HUB 视觉规则与本次架构内容分离 | PARTIAL | 基线提到 `“CSS 使用自定义属性集中管理颜色、间距、圆角和阴影，便于后续调整视觉主题”`，且有独立的 `“状态数据、节点选择、流程切换、逐步播放”` 数据驱动结构。这为分离提供基础，但未定义可跨主题复用的 HCH.HUB 视觉规则层，也未明确其与本次架构内容层的边界。 |
| 5. 定义自动校验以及桌面/移动端视觉验收 | PARTIAL | 基线定义了视觉验收：`“桌面浏览器下架构图层次清楚、文字可读；在常见手机宽度下内容不横向溢出”`。但验收方式为打开页面和人工检查，未定义任何自动校验。 |

## 实际缺失总结

最需要 Skill 修正的是：先用概念—关系—流程—权衡—结论建立内容模型，再按独立节点数选择纵向或横向结构；若选择横向，还需完整定义导航状态与输入方式，并补上自动校验和明确的视觉规则/内容规则分层。
