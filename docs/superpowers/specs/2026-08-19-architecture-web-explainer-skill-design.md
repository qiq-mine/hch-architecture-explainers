# 技术架构 Web 可视化 Skill 设计

## 目标

将复杂的技术栈、系统架构或运行流程整理为具有 HCH.HUB 2.0 视觉语言的单文件 Web 展示，并把本次 `skill-lifecycle.html` 的内容建模、交互选择、实现与验收方法沉淀为可复用 Codex Skill。

## 当前页面调整

在生命周期展示区顶部加入章节标题：

- 标题：`Skill 的发现、加载与执行机制`
- 副标题：`从能力匹配、主说明加载、资源按需展开，到真实执行与结果验证。`

标题属于整个流程区，不随单页 Slide 切换。现有 11 个流程节点继续使用横向 Slide，保留右下角上一页、页码、下一页导航，并支持键盘方向键与触控滑动。

流程开头补充启动阶段：用户任务或高优先级指令先进入 Agent，宿主已把可用 Skill 的 `name`、`description` 与路径轻量列表暴露给模型；用户可用 `@`/`$` 显式选择，或由任务语义匹配 `description` 隐式选择。选中后才加载完整 `SKILL.md`，不能表述成 Skill 自身持续扫描。

定位对比区使用 Prompt、Skill、Tool / MCP 与 Agent Loop 四个 Agent 运行概念，不再用不同抽象层级的“技术栈 / 框架”。边界列表统一正文与强调文字的中文字体、字重和行高。

## Skill 适用范围

Skill 在用户希望把以下信息制作成可交互 Web 展示时触发：

- 技术栈或系统架构
- Agent、RAG、数据平台等技术机制
- 生命周期、调用链、数据流或部署流程
- 技术方案对比、优缺点与边界

普通产品页面、后台 CRUD 页面以及仅需静态架构图的任务不触发此 Skill。

## 内容模型

先把原始资料整理为五类信息，再设计页面：

1. 概念：它是什么，解决什么问题。
2. 关系：与相邻工具、协议或技术栈如何分工。
3. 流程：输入如何经过阶段转化为输出。
4. 权衡：优势、限制和适用边界。
5. 结论：用户应记住的设计原则或行动建议。

页面可从 Hero、概念对比、流程展示、权衡和总结中按需选择，不要求为了完整而生成空洞章节。

## 流程展示策略

按照可独立理解的流程节点数选择交互形式：

- 1–3 个节点：使用正常纵向滚动。每个节点按阅读顺序进入视口，不添加横向导航。
- 4 个及以上节点：使用横向 Slide。一次展示一个完整阶段，右下角提供约 60% 默认透明度的上一页、页码和下一页导航；悬停或聚焦时恢复 100% 不透明度。

节点必须代表完整阶段，不能为了达到阈值机械拆页。横向模式同时支持按钮、左右方向键和触控滑动；首尾按钮具有禁用状态。页面其他章节仍按正常纵向滚动。

## 视觉与实现约束

- 交付为单文件 HTML，零框架、零构建步骤。
- 使用语义化 HTML、CSS 与 Vanilla JavaScript；需要数据关系图时可选 D3。
- 视觉默认采用 HCH.HUB 2.0：深海军蓝背景、高对比冷白文字、青色主强调、绿色成功态、橙色警示态、细边框与克制辉光。
- 中文是主要信息语言；英文只用于短标签、代码、协议名或技术术语。
- 适配桌面和移动端，并尊重 `prefers-reduced-motion`。
- 动效服务于状态变化，不能影响内容可读性和键盘操作。

## Skill 结构

个人 Skill 名称：`creating-architecture-web-explainers`

```text
creating-architecture-web-explainers/
├── SKILL.md
├── agents/openai.yaml
├── references/content-model.md
├── references/visual-system.md
├── assets/explainer-starter.html
└── scripts/validate-explainer.mjs
```

- `SKILL.md`：触发边界、核心流程、展示策略和验收要求。
- `content-model.md`：技术资料到页面叙事的映射方法。
- `visual-system.md`：HCH.HUB 2.0 设计令牌、组件和动效规范。
- `explainer-starter.html`：可删改的通用单文件起始模板。
- `validate-explainer.mjs`：检查单文件结构、关键交互、可访问性和脚本语法。

## 验证

Skill 采用流程文档 TDD：先让一个未加载 Skill 的独立场景生成技术架构展示，记录它在内容分层、流程模式选择或验收上的缺失；再加载 Skill 重跑同一场景，确认这些可观察行为得到改善。

最终验收包括：

- Skill 目录通过官方 `quick_validate.py`。
- 起始模板通过 `validate-explainer.mjs`。
- 当前 `skill-lifecycle.html` 通过原有视觉契约校验。
- 桌面端确认标题、Slide 导航和页码不遮挡内容。
- 移动端确认文字可读、按钮可触达、横向手势有效。
